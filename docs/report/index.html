Participate

Run it yourself, or point a coding agent at it.

git clone https://github.com/unitaryfoundation/stabrank
cd stabrank
# describe your decomposition in bounds/mybound.json
make fit BOUND=bounds/mybound.json ARGS=--write
make verify BOUND=bounds/mybound.json

fit solves for the exact coefficients, or tells you no exact combination of your terms reproduces the target. verify rebuilds the identity in exact arithmetic. If it passes, open a pull request adding the file and the leaderboard picks it up on the next build.

A bound the pipeline cannot check is recorded as cited and never takes a record.

A bound with no pull request was added to main directly; its adding commit is the provenance. A receipt is certs/<slug>.json, written by the verifier and keyed to the content hash of the submission file, so an edited bound shows a stale receipt until it is re-verified. Lean-tier bounds have their receipt under certs/lean-<module>.json instead.

Reproducing this page

make build                       # re-verifies every bound without a receipt
uv run --extra challenge python site_challenge/build.py --no-verify
uv run --extra challenge python autoresearch/summary.py --since 2026-09-15

The second command rebuilds the pages from docs/ledger.json and the receipts in certs/ without running any certificate; a bound with neither is listed above as unverified and left off the board.
