# research/t5_rank5: the rank-5 exclusion of |T>^5

The pipeline behind `bounds/qubit_T-m5-lower-6.json` (a bound only after
the pod run, the aggregate and the manifest): every rank-5 decomposition of
|T>^5 has, along qubits 1, 2 at the base point 00, three, four or five
visible terms (chi(T^3) = 3), so its base is a full 3-, 4- or 5-cover of
|T>^3 and the invisible terms lie on the six affine flats of F_2^2 missing
00. Stage (alpha) runs the 6,115,136 + 43,773 full 5-covers through
`verify_challenge/slice_cover.SliceMatcher`; stage (beta') runs the 4,709
full 4-covers with the invisible term on each of the six flats and stage
(gamma) the 4 full 3-covers with each of the 21 flat pairs through
`invisible.InvisibleMatcher`. The argument, the case split, the controls
and the soundness checklist are in `docs/notes/t5_rank5_exclusion.md`; the
design and its measurements are in `docs/notes/t5_rank5_feasibility.md`.

Files

| file | role |
|---|---|
| `common.py` | the cell (n_1 = 2, base point 00, orbit qubit_T), the six flats and 21 pairs, hashing, loaders, the exact re-decision of a hit |
| `invisible.py` | `InvisibleMatcher.run_one` (stage beta', one invisible term on a given flat, blocks for a repeated base state, the joint reconstruction of the ambiguous case) and `run_two` (stage gamma, two invisible terms on a given flat pair, the rank-2 residual scan, same-state and cancelling pairs); `PlantedInvisibleMatcher` for the planted control |
| `driver.py` | `degenerate --write`, `control-census`, `sample STAGE`, `partition`, `control-witness`, `control-planted`, `control-m4-pair`, `tables` |
| `degenerate5.json` | the stage B and C list: the 43,773 dependent or repeated full 5-multisets of \|T>^3, hashed |
| `partition.json` | the batches, hashed, with the census, degenerate list and 4-cover census hashes |
| `batch.py K` | one batch (`--resume`, `--max-seconds`, exit 2 on `DECOMPOSITION FOUND`, exit 1 on any undecided run) |
| `aggregate.py` | the certificate-side check and the batch manifest (`--dry-run --partial` during the run, `--recheck 2 --recheck-seed 20260924` at the end) |
| `probe.py`, `run.py`, `rank2_loop.sh` | the feasibility probes and the capped runner (`run.py --max-seconds 600 -- research/t5_rank5/driver.py CMD`) |
| `results/` | `census5_full.json` (the 5-cover census per pivot pair, the covers regenerated by the kernel), the probe records, `control_*.json`, `rates.json`, `sample_*.json`, `batch_K.json` and logs |
| `bounds/qubit_T-m5-lower-6.json`, `bounds/qubit_T-m6-lower-6.json` | the bound files, filled in after the run; `verify_challenge/cert_qubit_t_m5_rank5_attested.py` is their certificate |

Commands, in the order they were run on the laptop (all at nice 19, one
process at a time, through `run.py` with a 600 s cap):

```
uv run --extra challenge python research/t5_rank5/driver.py degenerate --write
uv run --extra challenge python research/t5_rank5/driver.py control-census
uv run --extra challenge python research/t5_rank5/driver.py tables
uv run --extra challenge python research/t5_rank5/driver.py control-planted --stage beta
uv run --extra challenge python research/t5_rank5/driver.py control-planted --stage gamma
uv run --extra challenge python research/t5_rank5/driver.py control-witness
uv run --extra challenge python research/t5_rank5/driver.py control-m4-pair
uv run --extra challenge python research/t5_rank5/driver.py sample A --count 200
uv run --extra challenge python research/t5_rank5/driver.py sample B --count 8
uv run --extra challenge python research/t5_rank5/driver.py sample C --count 12
uv run --extra challenge python research/t5_rank5/driver.py sample beta --count 30
uv run --extra challenge python research/t5_rank5/driver.py sample gamma
uv run --extra challenge python research/t5_rank5/driver.py partition --target-s 600 --pod-factor 2.0
uv run --extra challenge python research/t5_rank5/batch.py K            # one batch per stage as the pipeline test
uv run --extra challenge python research/t5_rank5/aggregate.py --dry-run --partial
```

The pod run and the final aggregate are section 8 of the exclusion note.
`STABRANK_NO_NATIVE=1` (or `batch.py K --no-native`) keeps the 5-cover
kernel and the stage A matcher in the Python reference; the deterministic
hash of a batch record does not depend on the path (the kernel-run and
modular-candidate counts sit outside it).
